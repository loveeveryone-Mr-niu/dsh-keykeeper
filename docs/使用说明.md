# 钥匙管家（dsh-keykeeper）使用说明与注意事项

> 版本 0.4.1 · 适用于 DSH Web（设置 → 钥匙管家）
> 一句话：把各家模型 API Key 加密存在本机，一键写进 DSH 模型配置，顺手看余额、跳官方充值页。

---

## 一、它能做什么

| 能力 | 说明 |
| --- | --- |
| 加密保险库 | 主密码派生密钥（scrypt N=65536）+ AES-256-GCM，`vault.json` 只存密文；默认 15 分钟无操作自动上锁，可在「设置」页改为 5 分钟 / 15 分钟 / 30 分钟 / 60 分钟 / 4 小时 / 不自动锁；**锁定后仍可只读查看已缓存的余额**（看 Key、刷新余额、导出仍需解锁） |
| 多平台 Key 管理 | 内置 22 个 API 平台 + 5 个订阅入口；支持逐条填写、粘贴 `keys.txt`、从文件导入 |
| 一键写入 DSH | 为每个平台生成供应商路由 `kk-<平台>` 与凭据 `KEYKEEPER_KK_<平台>_API_KEY`，写进 `llm-pi-ai` 配置，模型选择器立即可选 |
| 自动检测真实模型 | 保存 Key 后自动拉取该平台 `/models`，过滤非对话模型，挑 8 个写入；也可手动「检测并配置」 |
| 自选模型 | 「选择模型…」弹出平台全部对话模型，搜索/勾选后只写入所选，适合硅基流动这类模型市场 |
| 测试对话 / 设为默认 | 用真实 Key 发一条最小对话验证连通并显示耗时；一键把该模型设为 DSH 默认模型 |
| 余额 | 4 家能自动查：DeepSeek、Kimi/Moonshot、阶跃 StepFun、OpenRouter；硅基流动余额接口已下线，改为控制台跳转；其余给控制台入口；可自定义任意 OpenAI 兼容余额接口 |
| 充值 | 每个平台一张卡，「充值 / 控制台」按钮用系统浏览器打开官方页面；**只跳转，不代付** |
| 订阅记录 | ChatGPT / Claude Pro / Kimi Code / GLM Coding / MiniMax Plan 只做入口与手动记录（套餐、额度、续费日），不写模型路由 |

## 二、安装

### 已装在本机

当前以 `link:` 方式安装在 profile `desktop`，源码改动刷新页面即可生效（Host 端改动需在插件页禁用再启用）。

### 换电脑 / 重装

1. 先装好 DSH。
2. 把整个 `dsh-api管理器-11.26` 文件夹拷到新电脑任意位置（例如 `D:\tools\dsh-keykeeper`）。
3. 任选一种安装方式：
   - **图形界面**：DSH → 设置 → 插件 → 安装本地 bundle → 选择该文件夹；
   - **命令行**：双击 `scripts\install.cmd`（默认装到 `desktop` profile；其他 profile 用 `install.cmd -Profile 你的profile`）。
     - 不要直接双击 `install.ps1`，Windows 执行策略会拦；`install.cmd` 已用 `-ExecutionPolicy Bypass` 包了一层。
4. 浏览器按 `Ctrl+R` 刷新。
5. 如果侧边栏没有「钥匙管家」：设置 → 插件 → 找到 `dsh-keykeeper`，禁用再启用一次，然后 `Ctrl+R`。

> 插件文件夹里**没有你的 Key**。Key 在保险库文件里，见第五节「备份与迁移」。

## 三、第一次使用（5 步）

### 1. 打开面板

三个入口任选：

- 设置侧边栏 → **钥匙管家**（独立页）；
- 设置 → 模型 → 最下方「🔑 钥匙管家」卡片；
- 对话输入框旁的钥匙药丸。

### 2. 设主密码

- 至少 6 位，建议 10 位以上；主密码只用于派生密钥，**不落盘，忘记无法找回**。
- 设置页可以改主密码；改完旧备份仍可用旧密码打开。

### 3. 导入 Key

三种方式：

- **逐平台填**：密钥页选平台 → 粘贴 Key → 保存；
- **粘贴文本**：一行一个，`平台=key`，`#` 开头是注释；
- **从文件读取**：选本地 `.txt` / `.json` 文件。

示例 `keys.txt`：

```text
# 一行一个，平台名见面板里的英文小写 id
deepseek=sk-xxxxxxxx
moonshot=sk-xxxxxxxx
siliconflow=sk-xxxxxxxx
glm=sk-xxxxxxxx
```

可用别名（写别名也能识别）：`kimi`→moonshot、`glm`→zhipu、`qwen`→dashscope、`doubao`→volcengine、`claude`→anthropic、`grok`→xai 等。

订阅类（`chatgpt`、`claude-pro`、`kimi-code`、`glm-coding`、`minimax-plan`）会被跳过并提示原因——订阅没有可用的 API Key/端点，只做入口和额度记录。

### 4. 检测并写入 DSH

保存 Key 后插件会**自动检测**：向该平台请求真实模型列表，过滤掉向量/重排/绘图/语音模型，挑 8 个对话模型，自动写入 DSH 的 `kk-<平台>` 供应商并同步凭据。

- 成功提示：「发现 N 个模型，自动选 8 个」；设置 → 模型 里出现 `kk-<平台>`，对话输入框旁的模型选择器即可选。
- 想重跑：密钥页该平台卡片点 **「检测并配置」**。
- 想自己挑：点 **「选择模型…」**，在弹窗里搜索并勾选要写入 DSH 的模型（默认全不选，可全选/清空），保存后立即写入。
- 验证能不能真用：点 **「测试对话」**，显示 `✅ 1200ms · 模型名` 即通；失败会显示 HTTP 状态与原因（见下面错误表）。
- 想让它成为默认模型：点 **「设为默认」**（等价于 设置 → 模型 → 默认模型）。
- 写入失败时会把一段 YAML 显示出来，可手工粘贴到 `llm-pi-ai` 配置兜底。
- 换 Key 或从备份导入后，插件会自动同步已写入路由的凭据；若仍不生效，再点一次「检测并配置」。

**检测/测试失败怎么看**：

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `HTTP 401` | Key 无效或已删除 | 到平台控制台重新生成 Key，保存后会重新检测 |
| `HTTP 403` | 欠费、未实名或该 Key 无该模型权限 | 充值/实名后再试；确认模型对当前账户开放 |
| `HTTP 404` | 模型 id 不存在或平台接口路径变了 | 点「检测并配置」重新拉取；仍失败把提示发我 |
| `HTTP 429` | 触发限流 | 等几分钟再试 |
| 超时/网络错误 | 本机连不上该平台（可能需要代理） | 检查网络或代理设置 |
| `MISSING_CREDENTIAL` / `INVALID_CREDENTIAL` | 路由已写入但 DSH 找不到对应凭据 | 再点一次「检测并配置」；或设置页「运行自检」 |

### 5. 看余额 / 充值 / 自检

- **余额页**：点「刷新」；能自动查的显示金额，查不到的显示「控制台」。
- **充值页**：点平台卡片打开官方收银台或控制台。
- **设置页 → 运行自检**：写 DSH 没反应时先跑它，会检查 settings 服务、`llm-pi-ai` 入口、凭据服务、已写入路由。

## 四、换模型 / 删模型

插件本身不切换模型，只是把平台注册成 DSH 的「供应商」：

- **当前会话换模型**：对话输入框旁的模型选择器；
- **改默认模型**：设置 → 模型 → 默认模型，或密钥页点「设为默认」；
- **同平台换 Key**：密钥页改 Key → 保存（自动检测并同步凭据）；
- **不再用某平台**：密钥页删除该平台 → 会同时撤销 `kk-<平台>` 路由和对应凭据，模型选择器里消失；
- **订阅类**不会出现在模型列表里，这是正常的。

## 五、备份与迁移（换电脑重点）

### 文件在哪

| 文件 | 路径 | 内容 |
| --- | --- | --- |
| 保险库 | `%USERPROFILE%\.dsh\keykeeper\vault.json` | 加密后的 Key、订阅记录、充值链接覆盖 |
| 余额缓存 | 同目录 `balance-cache.json` | 余额数字与时间，不含 Key |
| 挂载戳 | 同目录 `last-mount.json` | 插件加载时间与版本，排查用 |

可用环境变量 `DSH_KEYKEEPER_VAULT` 把保险库指到任意路径（如 `F:\deepseekwork\vault.json`）。

### 三种迁移方式

1. **拷保险库（推荐）**：旧机把 `vault.json` 拷到新机同一路径 → 打开面板解锁，输入**原主密码** → 点「写入 DSH」（凭据和路由是每台机器本地的，必须重写一次）。
2. **导出明文备份**：旧机设置页「导出明文备份」（需再输一次主密码）→ 新机「导入备份」→ 设新主密码。明文文件包含真实 Key，按敏感文件保管。
3. **重新粘 keys.txt**：最省事但订阅记录和自定义接口不会带过去。

如果新机已经有库：先手动上锁，或在导入前把旧 `vault.json` 改名备份；导入覆盖前插件会自动留 `.bak-<时间>`。

## 六、余额与充值细节

### 能自动查余额的 4 家

DeepSeek、Kimi/Moonshot、阶跃 StepFun、OpenRouter。其余平台（智谱、MiniMax、硅基流动、火山、百炼、OpenAI、Anthropic、Gemini、xAI 等）没有可用的公开余额接口（硅基流动的 `/v1/user/info` 已于 2026-08-14 下线），只给「控制台」链接。

### 自定义余额接口（给中转站用）

设置页 → 自定义余额接口，字段：

- **URL**：必须 `https://`（本机 `localhost` 例外）；
- **请求头名 / 前缀**：例如 `Authorization` + `Bearer `（前缀末尾的空格会保留）；
- **JSON 字段路径**：例如 `data.totalBalance`；
- **币种**：CNY / USD；
- **Key**：单独填；只有该 URL 与某平台 `baseURL` 同 host 时才会复用平台 Key，否则只用自己的 Key 或匿名。

### 充值

只做跳转：点卡片用系统浏览器打开官方充值/控制台页面，登录后自己付款。插件不接触支付、不代付。

高级：保险库明文的 `ui.rechargeOverrides` 可自定义某平台的充值链接（导出明文 → 改 → 导入）。

## 七、常见问题

| 现象 | 处理 |
| --- | --- |
| 设置里没有「钥匙管家」/ 输入框没有药丸 | `Ctrl+R`；设置 → 插件确认 `dsh-keykeeper` 已启用；禁用再启用 |
| 点开提示未解锁 / 401 | 已自动上锁（默认 15 分钟无操作，可在「设置」里改或关掉），重新输主密码；不输密码也能在锁定页看缓存的余额 |
| 模型页没有 `kk-` 供应商 | 密钥页点「检测并配置」；仍无 → 设置页「运行自检」；失败时按 YAML 片段手工粘贴 |
| 余额显示「—」或「无公开接口」 | 该平台没有公开余额 API，点「控制台」看 |
| 余额报错 | 检查 Key 是否有效、接口 URL 是否 https、请求头前缀空格 |
| 用 curl 访问插件接口 401 | 正常：DSH 自带登录令牌，外部请求一律 401；请在页面内操作 |
| 忘记主密码 | 无法找回（不落盘）。只能删 `vault.json` 重建，Key 需重新填 |
| 卸载插件后 Key 还在吗 | 在。卸载不删 `%USERPROFILE%\.dsh\keykeeper\`，需手动删目录 |

## 八、安全与注意事项

1. **插件与 DSH 同权限**：能读本机文件、用凭据、访问网络。只从你信任的来源安装。
2. **Key 的存放**：加密的 `vault.json` + DSH 凭据库。界面只显示掩码；导出接口需要再次输入主密码。
3. **明文备份是敏感文件**：包含所有真实 Key，别放网盘/聊天记录。
4. **网络只去厂商官方域名**：余额与模型请求都发往你配置的平台域名；自定义余额接口是你显式配置的地址（强制 https，本机 localhost 例外）。
5. **不代付**：充值只打开官方页面，插件不碰支付。
6. **无遥测**：没有上报、没有统计。
7. **主密码建议 10 位以上**；旧库（N=16384）解锁后会自动迁移到 N=65536。
8. **管理接口只监听回环地址**：带 Host 回环校验、同源校验和 `x-keykeeper: 1` 头校验；其他来源一律 403。

## 十、卸载

- 设置 → 插件 → 禁用/卸载；
- 想连数据一起清掉：手动删除 `%USERPROFILE%\.dsh\keykeeper\` 目录；
- 卸载前建议先导出明文备份，或确认还记得主密码。
